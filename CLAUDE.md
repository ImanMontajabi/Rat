# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Rat is a macOS network monitor and reactive application firewall modelled on Little Snitch. It has no Network Extension entitlement (no paid developer account), so it cannot intercept connections before they start; see `docs/ARCHITECTURE.md` sections 7-8.

## Mandatory Proven Verification & Non-Regression Policy

These rules apply to every change. A change that does not meet them is not done, whatever its tests say.

- **Never present a feature, bug fix or optimization as done without proven verification.** Every change needs all three, reported in the PR's checklist with the commands and their results:
  1. **Automated tests:** unit or integration tests for the new behaviour (`xcodebuild -scheme Rat test`, `(cd RatFilter && swift test)`, `python3 -I -m unittest discover -s scripts -p 'test_*.py'` for scripts).
  2. **UI tests** when a change touches views or the state they show: `scripts/test-ui.sh` passes, with new accessibility identifiers and UI tests for new controls.
  3. **Live verification** against the installed app and helper: the Release build (`scripts/build-release.sh`) in `/Applications`, the helper updated from it (Settings > Security; the user enters the password), and the behaviour observed for real (daemon status file, `scripts/rat-status.sh`, screenshots, real apps). Steps that need root are run by the user (`! sudo …`), never skipped: if a live check could not be done, the PR says so and the change is not called done.
- **Zero regression tolerance.** Every bug fix and optimization runs the full existing suites (the three above, plus `scripts/test-ui.sh` and the goldens) and the PR reports their counts. Firewall enforcement (`scripts/verify-blocking.sh` for changes to blocking), helper sync, VPN and proxy tags, the process tree and rules must still work; a failing or newly skipped test blocks the PR until it is fixed, not re-recorded or disabled to pass.
- **Resource discipline.** Every PR measures `Rat.app` and `rat-enforcerd` with `scripts/measure-resources.sh 60` (CPU average and peak in %, RSS average and peak in MB) on the installed build before and after the change, under the same conditions, and reports both in the PR. A rise needs a reason in the PR.

## Workflow (mandatory)

GitHub rulesets protect `main` and `release`: no direct pushes, no force pushes, no deletion. Every change goes through a pull request.

- **Branches:** `main` is integration, `release` is the stable line. Work on `feat/<name>`, `fix/<name>`, `ci/<name>`, `test/<name>` or `docs/<name>`, branched from an up-to-date `main`; one logical change per branch. Never commit on `main` or `release`.
- **Changelog fragment:** every branch adds `changelog.d/<slug>.<type>.md` (types: added, changed, fixed, removed, security, internal; see `changelog.d/README.md`). `scripts/changelog.py new <type> <slug> "…"` creates one; `scripts/changelog.py check --base origin/main` is what CI runs. Only a PR that changes nothing for anyone may use the `skip-changelog` label instead.
- **Version:** the root `Version` file (`X.Y.Z`, no extension) is the single source of truth and holds the version being developed on `main`. `scripts/version.sh set X.Y.Z` writes it and `project.yml`'s `MARKETING_VERSION`; `scripts/version.sh check` fails when they differ.
- **Pull request:** push the branch and open it with `gh pr create --base main` (fill in `.github/pull_request_template.md`: summary, architecture, checklist). Merge only when CI is green. Commits and PR bodies keep the attribution lines.
- **Releases:** a merge into `main` publishes a nightly pre-release. A stable release is a PR from `main` into `release`: the release workflow publishes `v<Version>` when `Version` is higher than the last stable tag, then opens a PR back to `main` that compiles the fragments into `CHANGELOG.md` and bumps `Version` to the next minor. Merging into `release` publishes a release: only the maintainer does it.
- **UI tests:** `scripts/test-ui.sh` runs `RatUITests` (XCUITest, scheme `RatUITests`, configuration `UITest`: a Debug build with bundle id `com.imanmontajabi.Rat.uitest`, so the running Rat is never quit and its preferences are separate) on demo data, then the snapshot goldens. It needs a logged-in GUI session, so CI does not run it: run it before opening a PR that changes UI, and keep hands off the keyboard and mouse while it runs (it types into the app in front). It switches a non-Latin keyboard layout to U.S./ABC for the run (`scripts/input-source.swift`) and restores it; the tests launch with `-ApplePersistenceIgnoreState YES` so a window minimized in an earlier run does not come back minimized. UI tests find elements by accessibility identifiers (`app-row-<name>`, `process-row-<name>`, `remote-row-<host>`, `disclose-<name>`, `policy-deny`/`policy-allow`, `search-field`, `route-filter`, `time-range`, `inspector-title`, `profile-<name>`, `map-places`: the map's places as its value, `summary-counts`, `summary-filtered`); keep them when changing views, and never click Install/Update/Remove Helper or Download in a UI test.
- **CI (`.github/workflows/`):** `ci.yml` runs on every PR: the fragment and Version checks (Ubuntu), `swift test` and `xcodebuild -scheme Rat test` (macOS; `TEST_RUNNER_RAT_SKIP_GOLDENS=1` because snapshot pixels depend on the display scale and Xcode, so goldens are compared only locally), and a Release build packed into a DMG that is attached to the run. `nightly.yml` (push to `main`) publishes `v<Version>-nightly.<YYYYMMDD>.<sha>` as a pre-release with the DMG, `.sha256` and the notes rendered from the fragments, keeping the newest five. `release.yml` (push to `release`) does the stable release described above. `security-audit.yml` (Mondays 08:00 UTC, on demand, and on PRs that change dependencies, workflows or the audit script) runs `scripts/security-audit.py`: GitHub Advisory Database advisories for every pinned Action (an Action not pinned to a full SHA with a `# vX.Y.Z` comment is a finding) and osv-scanner (pinned version and checksum) for package lockfiles; a scheduled or manual run with findings opens or updates the `security` issue, and a PR with findings fails. All builds share `.github/actions/setup-macos` (newest stable Xcode, XcodeGen, create-dmg, DB-IP cached per month), `scripts/build-release.sh <out> [build]` and `scripts/make-dmg.sh <Rat.app> <out.dmg>`; run the two scripts locally for the same build. Actions are pinned to commit SHAs.

## Architecture

- `RatFilter/` is a Swift package: `RatFilterCore` (pure rule engine: `Rule`, `RuleSet` with profiles/groups/triggers, `RuleEngine`, import/export), `RatMonitor` (libproc `ConnectionSampler`, `nettop` `TrafficSampler`, `SystemSnapshot` parser for the root helper's lsof output), `RatGeo` (own `.mmdb` reader), `RatFilterExtension` (dormant `NEFilterDataProvider`).
- `App/Model/Ledger.swift` is the hub: samples every 1.5 s, groups processes into apps (`AppIdentity` = outermost `.app`), evaluates each remote against `RulesModel.engine`, raises alerts for `.ask`, hands the helper the denied apps and the local ports of rule-denied sockets (`refreshEnforcement`).
- UI: `SidebarView` (monitor left pane, toolbar rows start below the traffic lights), `RulesWindow` (sidebar + table, Little Snitch layout), `SettingsWindow` (⌘,, `Settings` scene; tab names follow Little Snitch's `Settings.strings`). Preferences live in `AppSettings` (UserDefaults).
- New installs default to Silent Allow (`RuleSet.version` 2; version 1 files migrate). Alerts are re-validated every tick (`AlertCenter.revalidate`) so an app with a rule never prompts.
- Chart: `Ledger.chartLayout` tiles the window with bars and shrinks it to the data that exists.
- `RulesModel` wraps the engine for the UI (policy buttons are a whole-app rule, `processPolicy`/`connectionPolicy` the rows under it with `Endpoint`; alerts create scoped rules). `approved` is a review marker only: `enabled` gates matching, imported rules arrive disabled+unapproved.
- `RatFilter/Sources/RatEnforce` + `Enforcerd/main.swift` build `rat-enforcerd`, the root daemon (KeepAlive LaunchDaemon `com.imanmontajabi.rat.pf`): it reads `denied-apps.txt` (written by `Ledger.deniedAppPaths`) and `denied-ports.txt` and keeps the pf anchor in step by blocking the local ports of every socket of denied apps. **Rat never blocks remote addresses** (no table, no `pass` rules, no `pfctl -k`): an address is shared by every app, DNS included. `ProcessGrouping` (RatMonitor) decides which app a process belongs to for both the app and the daemon (`companionApp`: programs an app runs from outside its bundle, such as Windscribe's tunnels in /Library/Application Support/Windscribe/bin). `scripts/verify-blocking.sh` is the live test (needs sudo); `scripts/rat-status.sh` shows what is enforced (the daemon's status file `/var/run/com.imanmontajabi.rat.enforcer.json`). The process list's ✗/✓ (`Rule.listLevel`: `.app`, `.process` for one executable of the app via `Rule.executable`, `.connection` for one process + server + port + protocol; a hand-written whole-app rule counts as `.app`) decide first, narrowest level first, over the app's other rules from alerts (`RuleEngine.decide`; a ✓ does not lift a deny rule for any process). `Connection.executable` is the process holding the socket, and `Rule.processPath` matches it too, so a rule for one system service or helper path matches. An app ✗ with a narrower ✓ (`RulesModel.hasNarrowerAllow`) is not blocked as a whole: only the sockets the rules deny, through `denied-ports.txt`. The daemon also blocks a denied app's loopback TCP connections to other programs on lo0 (local proxies, `ssh -L`). `PFHeal` (watchdog every 2 s) keeps pf on and `com.apple/*` hooked when a VPN client (Cloudflare WARP) stops pf or overwrites the main ruleset: pf off → turn on (load /etc/pf.conf first if another program's rules are left in it); pf on without Apple's anchors → reload NAT+filter (`pfctl -N -R`) with Apple's anchors plus the other program's; a main ruleset with rules of its own is only replaced by Settings > Security's Repair Firewall Now (`--repair` file, touched by `Enforcer.requestRepair`). A `pass … quick` evaluated before `anchor "com.apple/*"` (in the main ruleset, or in another program's anchor listed first: `PFHeal.shadowingRule`) counts as unhooked: anchor points only → Apple's go first again, otherwise reported. The watchdog also reads `com.apple/rat` back (`PFRules.holds`) and loads it again when pf dropped its rules while the ports stayed the same. Never `pfctl -d`, never edit /etc/pf.conf.
- Proxy unmasking (1.1.0): `ProxyWatch` (RatEnforce) reads proxy requests on lo0 through BPF (`LoopbackFilter`, `ProxyHandshake`) and publishes the user's proxied flows in `/var/run/com.imanmontajabi.rat.proxied.json` (0600, `--owner-uid`); `ProxyUnmasking` (app) merges them, with a `KERN_PROCARGS2` fallback (`ProcessArguments`), into `RemoteHost.via`. `scripts/test-proxy.py` is the local test proxy for `verify-blocking.sh` phase 3.
- `Enforcer` writes `denied-apps.txt` / `denied-ports.txt` and installs the two opt-in root LaunchDaemons (`rat-enforcerd`, and `App/Resources/rat-pf-helper.sh snapshot`). Never run the install paths in tests. Update Helper is decided by SHA-256 (`FileDigest`), never by a version number: the bundled `rat-enforcerd` against the installed file and against the running daemon's `EnforcerStatus.executableSHA256` (`Enforcer.outdatedReason`; under tests only with `HelperFiles` given). Settings > Security, the Inspector and the sidebar footer show it.
- Preferences go through `Preferences.store` (a separate suite under XCTest and in demo mode): tests must never write the user's real defaults. Demo mode (`Preferences.isDemo`, Debug + `RAT_DEMO_MAP`) also uses a temporary data folder, sees no helper and refuses every privileged step (`Enforcer.runPrivileged`), so UI tests can click anything.
- Offline geo: `GeoService` reads `Contents/Resources/Vendor/dbip-city-lite.mmdb` and `dbip-asn-lite.mmdb` (or `RAT_GEOIP_DB` / `RAT_GEOIP_ASN_DB`), or the user's files from Settings > GeoIP (`GeoDatabases`, copied into `GeoIP/` in the data folder, validated, never overwritten while mapped). The MMDB reader treats files as untrusted (bounds checks, decode budget). The Mac's own position comes from the time zone (`/usr/share/zoneinfo/zone.tab`).
- Connection details (1.2.0): `PortNames` (usual service per port), `RemoteHost.pid/process` ("via <helper>"; the macOS row is grouped by service, `SharedServices` marks services that work for other apps, and the macOS row has no one-click Deny), `RemoteHost.network` (ASN), `RemoteHost.route` from `RouteMarker`/`NetworkRoutes` (socket on a tunnel interface → VPN, named via the tunnel's kernel-control owner, also published by the helper as `tunnels`; system proxies from `SCDynamicStoreCopyProxies`).
- Process tree (1.3.0): `AppEntry.processes` (`ProcessStats` per executable name: pids, traffic) and `AppEntry.tree` (main process's remotes + `ProcessNode`s; none for command-line tools, no main process for macOS). `RemoteHost.bytesIn/Out` come from nettop's per-connection rows (`TrafficSampler.sampleWithFlows`, matched by `FlowCounter.key`: pid, proto, local port, remote port). `MonitorSelection` (app / process / remote) scopes `MapPane` and `InspectorView` (`ProcessInspector(process:)`, `RemoteInspector`). `AppEntry.launchedBy` (`ProcessGrouping.launchingApp`) is display only: a CLI tool's rules stay its own.
- Route tags (1.3.0): `RemoteHost.route` is a `RouteTag` (`.vpn(name, interface)`, `.systemProxy`, `.localProxy(program, listener)`; `label` is the alert wording, `badge`/`shortBadge` the tag). `RouteMarker.localProxy` tags loopback connections to another program's listener when `NetworkRoutes.localProxyProgram` knows it (ssh, Tor, Clash, …). `RouteFilter` (search words `vpn`, `proxy`, `is:vpn`, `is:proxy`, or the route chip) filters apps and tree rows; `RouteBadges` draws a connection's tags, `RouteSummaryBadges` an app's or process's (distinct tags, VPN first; folds to a count, then symbols, so the name keeps its room). A connection is `.vpn` when its local address is a tunnel's; with no local address (`*`, `0.0.0.0`) the routing table decides (`NetworkRoutes.routeInterface(to:)`, PF_ROUTE `RTM_GET`, cached until the marker's 5 s refresh; loopback and link-local never). The tunnel client's own connection to a public server is `.vpnServer(name)` (the carrier: neither `isVPN` nor `isProxy`); `NetworkRoutes.internetTunnel()` is the tunnel that carries the default route. `MonitorFilter` (search, chips, time range; owned by `MonitorWindow`) is the one filter for the list and `MapPane`, which draws only the listed apps' matching connections, and for the inspector's Summary (`Ledger.summary` → `MonitorSummary`; with a search or chip on it counts the listed apps and matching connections, using `RemoteHost.verdict` from the last pass). A local proxy's one outside connection is its server (`ProxyHop.server`) unless it is the destination itself (same address, or the destination's port from a program that is not a known tunnel).
- Live proxy tests: `AppTests/LiveProxyTests` run real `curl` through `HoldingProxy` (a loopback SOCKS5/HTTP CONNECT proxy in the test that never connects anywhere, 127.0.0.1 and ::1); the helper half reads `/var/run/com.imanmontajabi.rat.proxied.json` and skips where the helper is not installed (CI).
- Host names: `HostNames` (Geo.swift) never blocks a pass. `lookup` returns the address until a background reverse lookup (an `OperationQueue`, four at a time) answers; loopback, unspecified and link-local addresses are never looked up (`hasNetworkName`). The ledger judges a connection whose name is pending on a later pass, at most `HostNames.grace` (3 s) later, so domain rules match and alerts are named.
- All user data lives in `~/Library/Application Support/com.imanmontajabi.Rat`. `~/Library/Application Support/Rat` belongs to something else; do not touch it.
- `screenshot/` (git-ignored) holds the raw Little Snitch reference screenshots; `SnapshotTests` read them when present.
